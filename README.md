# ケイトホーム 経営ダッシュボード(土台)

マスターのスプレッドシートに入力 → このアプリで見る(基本は読むだけ。「反響を登録」画面だけ、新しい反響をスプレッドシートに書き込みます)。
あなた本人のGoogleアカウントでログインした時だけデータが表示されます。PC もスマホ(Galaxy)も同じアプリです。

- 入っている画面(アプリ・webとも同じ順番): ホーム(案件アラート:ポータルの見積り忘れ・キャンセル期限) / 反響を登録(区分・媒体・邸名・担当などを選んで、新しい反響を1件その場でスプレッドシートに書き込む。現調日・見積り・結果はこれまで通りスプシへ) / 顧客登録(契約日・顧客名・契約金額・集客経路・担当・住所・電話番号を入れると、その場で契約日順に顧客シートへ書き込む。残りの項目はこれまで通りスプシへ) / 経費入力(費目をタップで選んで金額・日付(カレンダー)を入れると、その場で経費データに日付順で書き込む。法人税・設立費はここでは入力できない) / 発注タスク(入金がまだの案件ごとに、契約後の発注・準備タスクをチェックリストでタップして消し込む。完工していても入金が済むまでは表示されたまま) / メンテ(完工の1か月後・5年後・10年後の点検アラート) / 顧客(検索と、区市・状態・集客経路・担当・契約年での絞り込み。はじめに入金がまだの顧客だけを表示し、入金済みは「もっと見る」で表示。押すと顧客シートの情報がすべて見られる。電話→発信、住所→Googleマップ。見るだけ) / 売上(年ごとの 担当×月。売上・粗利・累計売上、本数は( )、合計とPH=月平均) / 着工粗利 / 案件(反響のうち「連絡つかず」「成約」以外の、まだ動いている・結果待ちの案件一覧。自社・ポータル・訪販をタブで切替) / 入出金 / 利益率(担当者ごとのタブと全体) / 集客分析(成約率 / ポータルの 番手×紹介数 の成約率) / 年間収支(年別シートの月別表で固定費・変動費を全項目表示 / 何にいくら使ったか(構成比・前年同期との差)/ ガソリン代・駐車場代・飲食費などの月ごとの推移と平均) / 割合(集客経路ごとの契約件数・割合・売上・利益・利益率。追加・下請けは除く) / チラシ・折込(媒体ごとの予算・枚数・反響・成約率・ROI(利益÷予算)。累計/各年で切替。成約率・ROIは、反響・成約とも入力済みの回だけで計算) / インセン(担当者×月の明細。「PDFをダウンロード」でA4横のPDFを保存) / 施工地図(町名・丁目ごとに邸を並べる。完工日が空欄の邸は青、その邸がある町名はオレンジの枠。A4・1枚のPDFを保存) / 口コミ(書いてくれた割合・何人に1人・〇あり/なしで絞れる契約の一覧。住所を押すとGoogleマップ) / ランキング(職人=塗装職人への発注額を契約年ごとに。カラー=外壁色・屋根色・カバー色)
- 画面だけ試す: アドレスの最後に `?demo=1` を付ける(架空データが出ます)
- GitHub に置くのは「画面のプログラム」だけで、売上などの**データは入っていません**

## しくみ

```
マスターのスプレッドシート(Google) ←ここに入力(と、「反響を登録」画面からの書き込み)
        ↑ 読み書き
Apps Script(小さな受付係。許可したメールの本人にだけデータを渡す/反響を書き込む)
        ↑ Googleログインの証明を添えて依頼
GitHub Pages のアプリ(このフォルダ。PC・スマホ共通)
```

## 手順

### 1. スプレッドシートを用意する

1. `統合マスター(移行用).xlsx` を Google ドライブにアップロード
2. ダブルクリックで開き、「ファイル → Google スプレッドシートとして保存」
3. このシートを新しいマスターにしていく(古い管理表は、もう更新しない)
4. **このマスターは、あなただけが見られる状態のままにする(誰にも共有しない)**

#### 1-2. ポータル専用のスプレッドシート(ポータル担当のスタッフに共有するのはこちらだけ)

1. `ポータル管理(ポータル担当共有用).xlsx` も同じ手順で Google スプレッドシートにする
2. 右上「共有」から、ポータル担当のスタッフを「編集者」で追加(マスターは共有しない)
3. そのスプレッドシートのURL `https://docs.google.com/spreadsheets/d/【ここ】/edit` の【ここ】(ID)をメモ。手順3で `PORTAL_SHEET_ID` に入れる

### 2. Google のログイン用IDを作る(初回だけ)

1. https://console.cloud.google.com/ を開き、新しいプロジェクトを作る(名前は何でも可)
2. 「APIとサービス → OAuth 同意画面」→ ユーザーの種類「外部」→ アプリ名と自分のメールを入れて保存。公開ステータスは「テスト」のままで構いません。「テストユーザー」に**自分のGmailを追加**
3. 「認証情報 → 認証情報を作成 → OAuth クライアント ID」→ 種類「ウェブ アプリケーション」
4. 「承認済みの JavaScript 生成元」に `https://<GitHubのユーザー名>.github.io` を追加して作成
5. できた「クライアント ID」(`〜.apps.googleusercontent.com`)をメモ

### 3. Apps Script を設置する

(Googleスプレッドシートの言語・地域は日本、タイムゾーンは「(GMT+09:00) 東京」にしておいてください。ファイル → 設定。経費データの日付が今日の日付で自動的に入るために使います)


1. 手順1のスプレッドシートで「拡張機能 → Apps Script」
2. 最初から入っているコードを消して、`apps-script/Code.gs` の中身を貼り付けて保存
3. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」に3つ追加
   - `CLIENT_ID` = 手順2でメモしたクライアント ID
   - `ALLOWED_EMAILS` = あなたのGmail(見せたい人が増えたらカンマで区切って追加)
   - `PORTAL_SHEET_ID` = 手順1-2のポータル専用スプレッドシートのID(アプリは、あなたの権限でそちらも読みます。ポータル担当のスタッフにはマスターの中身は見えません)
4. 右上「デプロイ → 新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**(ログインの本人確認はスクリプト側で行い、許可したメール以外には何も返しません)
5. 表示された「ウェブアプリのURL」(`…/exec`)をメモ。初回はGoogleの許可画面が出る(ほかのスプレッドシートを読む許可を含む)ので許可

コードを直したときは「デプロイ → デプロイを管理 → 編集 → 新バージョン」で更新します。

**アクセスログ**: ログインが通ってデータを渡すたびに、マスターのスプレッドシートに「アクセスログ」という隠しシートを自動で作り、日時とメールアドレスを1行ずつ記録します(準備は不要です。上のコードを貼り替えて新バージョンを配布するだけで動き始めます)。見るには、スプレッドシートの左下「すべてのシート」の一覧から「アクセスログ」を選んで「再表示」してください。直近2000件を超えたら古い記録から自動で消えます。

**反響を登録**: アプリの同名の画面から、区分(ポータル/自社/訪販)・媒体・邸名・担当などを送ると、Code.gs がその区分に合うタブ(ポータルは手順1-2の専用スプレッドシート)の一番下に1行追加します。列はタブの見出し行(1行目)の名前で合わせているので、見出しを増やしたり並べ替えたりしても、名前さえ合っていれば動きます。現調日・見積日・結果などは登録できないので、これまで通りスプレッドシート側で入力してください。

**発注タスク(タスク)**: これまで Google Keep でやっていた「契約後の発注・準備の抜け漏れチェック」を、マスターの中でできるようにする機能です。顧客シートの行に「契約日」と「顧客名」の両方が入ると、Code.gs が自動で「タスク」という新しいシート(隠しではありません)に、決まった項目(粗利予想・顧客名簿・スキャン・4分割・職人発注・足場発注・DropBox・年賀状・地図・マップ・ドライブ・見本板発注・見本板届け・足場越境・打ち合せ・打ち合わせ書職人送信・塗料発注・足場現調・車・挨拶・フェンス・着手・完工・BeforeAfter の24個。左右裏の挨拶や洗浄挨拶・養生説明はまとめて「挨拶」1つです)を1行ずつ書き込みます(同じ案件で二重に作ることはありません)。その案件だけ増やしたい項目があれば、「タスク」シートに手動で行を追加してください(顧客名・契約日・項目を合わせれば、アプリ側にもそのまま表示されます)。アプリの「発注タスク」画面はチェックボックスをタップするだけで、スプレッドシート側の「完了日」列に今日の日付が入ったり消えたりします。対象は入金日がまだの案件だけです(完工していても、最後の「完工(完工入金)」タスクが残っている間は表示され続けます)。

この機能を有効にした最初の1回だけ、スプレッドシートのメニュー「ケイトホーム → 未入金案件のタスクを作る(足りない分だけ)」を押してください。今すでに契約が決まっている(まだ入金されていない)案件ぶんのチェックリストが、まとめて作られます(Google Keep からの移行用です。2回目以降に押しても、すでにある分は増えません)。

**経費入力**: アプリの同名の画面から、費目(ガソリン代・駐車場代・高速代・備品代・飲食費・租税公課・交通費・プリント代・車両代・消耗品費・福利厚生費・印紙代・携帯代・交際費・宿泊費・車両費・その他)を選んで金額と日付を送ると、Code.gs が「経費データ」シートに**日付の並び順を保ったまま**書き込みます。同じ日付の行がすでにあれば、その行の同じ費目のセルに金額を足し込みます(同じ日に同じ費目を2回入れても上書きされず合算されます)。無ければ、日付順で正しい位置に新しい行を差し込みます(あとから前日・前々日の分を入力しても、1行ずれて正しい位置に入ります)。曜日・合計などの列に計算式が入っている場合は、隣の行から式を引き継ぎます。法人税・設立費はアプリの選択肢に出しておらず、これまで通りスプレッドシート側で入力してください。

**顧客登録**: アプリの同名の画面から、契約が決まった案件を1件、契約したてに分かる項目(契約日・顧客名・契約金額(万円)・集客経路・担当・住所・電話番号)だけ入力して送ると、Code.gs が「顧客」シートに**契約日の並び順を保ったまま**書き込みます(経費入力と同じ仕組みです。あとから過去の契約日の案件を入力しても、正しい位置に差し込まれます)。材料費・職人発注・色・完工日・入金日などの残りの項目は、これまで通り進みながらスプレッドシート側で入力してください。契約日・顧客名がそろうので、発注チェックのタスクも自動で作られます。

### 4. アプリに設定を書く

`js/config.js` を開いて2つを入れます。

```js
APPS_SCRIPT_URL: 'https://script.google.com/macros/s/……/exec',
GOOGLE_CLIENT_ID: '……apps.googleusercontent.com',
```

この2つは公開されても悪用できない値です(ログインしていないとデータは返りません)。

### 5. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る(Public)。このフォルダの中身を全部アップロード
2. 「Settings → Pages → Branch: main / (root)」で保存
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

### 6. Galaxy(Android)にアプリとして入れる

1. Chrome で上のURLを開き、ログインして表示されることを確認
2. 右上「︙」→「アプリをインストール」または「ホーム画面に追加」
3. ホーム画面のアイコンから、アプリとして起動できます

## アラートの入力のしかた

- アフターメンテ: 顧客の「メンテ1か月」「メンテ5年」「メンテ10年」(AQ・AR・AS列)に、点検した日か記号(○など)を入れる。何か入っていれば消える(予定日は完工日から自動)
- ポータルのキャンセル: 紹介日から6日たっても「結果」が空欄の案件を知らせる(7日を過ぎると課金)。結果に何か入れると消える
- ポータルの見積り: 現調日から7日たっても見積日が空の案件を知らせる。見積日を入れると消える
- 自社の反響は、現調時に見積日を決めるのでアラート対象外
- 日数などは「設定」シートの『値(入力)』で変えられる
- 経費データは、費目の金額を入れると日付(A列)が今日の日付で自動で入る(Code.gs の onEdit)。入金・出金は1つの「入出金」シートに1行ずつ入力し(種別で入金/出金を選ぶ)、金額を入れると日付が同じように自動で入る。月次の入金・現場支払・固定費・広告費は、非表示にしてある年別シート(2024〜2027)に入力する(見るのは「年間収支」シートで、左上の黄色いマスで年を選ぶ)。アプリはこの年別シートを読む
- 自社・訪販は、結果に応じて行の色が自動で変わる(条件付き書式)
- 反響は「自社」「訪販」のタブ(ポータルはポータル担当のスタッフと共有する別ファイル)に、一番下の空いている行へそのまま入力する(行を足す必要なし。日付形式・プルダウンは2000行目まで設定済み)。区分の列は無く、タブ名で決まる
- アプリの「入出金」画面: 総未入金・総未出金、入金日が入っていない案件ごとの残り(案件をタップすると入出金の明細)、入出金の記録(新しい順)。顧客シートにない名前を入力すると画面の上に知らせる
- 入出金の顧客名とインセン調整の顧客名のプルダウンは、スプレッドシートを開き直して上のメニュー「ケイトホーム」→「顧客名のプルダウンを設定」を1回押すと自動で作られる(初回は権限の許可が出るので許可する)
- 発注チェックのタスクは、顧客シートで契約日・顧客名がそろった行に自動で作られる(手入力は不要)。今すでにある未入金の案件ぶんは、メニュー「ケイトホーム」→「未入金案件のタスクを作る(足りない分だけ)」で1回だけ作る
- アプリの「インセン」画面: 着地利益×歩合率(通常20%、ポータル系10%)、クロ40%:アポ60%、入金日の翌月に計上。金額を変えたい案件は、スプレッドシートの「インセン調整」(顧客名/対象(クロ・アポ、空欄なら案件全体)/上書きする金額(円)/理由)に入れると、アプリの計算より優先されPDFに「調整あり」と出る。担当者の選択肢から外したい名前は、設定シートに項目「インセン対象外の担当」(値=名前。複数はカンマ区切り)の行を足す
- IDの入力は不要。反響と顧客は邸名(苗字)と日付でアプリが自動で結びつける。入出金は「顧客名」(苗字+邸。顧客シートで入金日が入っていない案件がプルダウンに出る。地域は顧客の住所から自動。右側に総未入金・総未出金と案件ごとの残が自動で出る)で、インセン調整は顧客シートの名前(プルダウン)で案件を指定する

## 注意

- `tests/real.json` や `.xlsx` など**実データはリポジトリに入れない**でください(`.gitignore` 済み)
- ログインの有効期限は約1時間です。切れたら自動でログイン画面に戻ります
- 完工日が入っていない案件は、利益率の計算に入れません(案件の件数には数えます)。経費が確定していないためです
- 数字の決め方(追加・下請けの扱い、成約率、利益率、契約月ベースなど)は、スプレッドシートの「設定」シートに書いてあるルールと同じです

## ポータル管理シート側のスクリプト(apps-script/PortalCode.gs)

- 塩野さんと共有している「ポータル管理」のスプレッドシートに貼るスクリプトです(統合マスターの Code.gs とは別)
- 「結果」を『キャンセル』にすると、その行が「キャンセル」タブへ日付つきで移ります
- 「初期設定」を1回押すと、「紹介数」「番手」の列(プルダウンつき)と、結果のプルダウンの『キャンセル』が足されます
- インセンの担当は js/config.js の INCENTIVE_PERSONS(今は塩野だけ)。設定シートの任意の行: 「インセン対象」(値=インセンを出す担当。あれば config.js より優先)/「現役の担当」(集客分析・インセンの担当の選択肢を固定)/「担当の開始月」(PHの月数の数え始め。例: 塩野=2024-08)

## 開発者向け

```
node --test tests/engine.test.mjs          # 計算ロジックのテスト
node tests/code_gs_check.mjs               # Code.gs の認証・アクセスログ・反響登録・発注チェック・経費入力・顧客登録のテスト(模擬環境)
node tests/portal_gs_check.mjs             # PortalCode.gs の行の移し方のテスト
KATE_REAL_JSON=/手元/real.json node --test tests/engine.test.mjs   # 実データと既存シートの数字を突き合わせ(手元だけで)
python3 tests/make_sample.py               # 練習用データを作り直す
```

- `js/engine.js` … 計算(画面に依存しない)
- `js/screens/*.js` … 各画面
- `js/ui.js` … 表・グラフ部品(棒グラフは自前のSVG。マウスや指で数字が出ます)
- 新しい画面は `js/screens/` に足して `main.js` の `ROUTES` に1行足すだけです
