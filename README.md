# ケイトホーム 経営ダッシュボード(土台)

マスターのスプレッドシートに入力 → このアプリで見る(アプリは読むだけ)。
あなた本人のGoogleアカウントでログインした時だけデータが表示されます。PC もスマホ(Galaxy)も同じアプリです。

- 入っている画面: ホーム(案件アラート:ポータルの見積り忘れ・キャンセル期限) / メンテ(完工の1か月後・5年後・10年後の点検アラート) / 売上(月×担当) / 集客分析(成約率) / 利益率(担当者ごとのタブと全体) / 入出金 / 年間収支(年別シートの月別表。固定費・変動費は開いて項目を確認) / インセン(担当者×月の明細。「PDFをダウンロード」でA4横のPDFを保存)
- 画面だけ試す: アドレスの最後に `?demo=1` を付ける(架空データが出ます)
- GitHub に置くのは「画面のプログラム」だけで、売上などの**データは入っていません**

## しくみ

```
マスターのスプレッドシート(Google) ←ここに入力
        ↑ 読むだけ
Apps Script(小さな受付係。許可したメールの本人にだけデータを渡す)
        ↑ Googleログインの証明を添えて依頼
GitHub Pages のアプリ(このフォルダ。PC・スマホ共通)
```

## 手順

### 1. スプレッドシートを用意する

1. `統合マスター(移行用).xlsx` を Google ドライブにアップロード
2. ダブルクリックで開き、「ファイル → Google スプレッドシートとして保存」
3. このシートを新しいマスターにしていく(古い管理表は、もう更新しない)
4. **このマスターは、あなただけが見られる状態のままにする(誰にも共有しない)**

#### 1-2. ポータル専用のスプレッドシート(ポータル担当のスタッフに共有するのはこちらだけ)

1. `ポータル管理(ポータル担当共有用).xlsx` も同じ手順で Google スプレッドシートにする
2. 右上「共有」から、ポータル担当のスタッフを「編集者」で追加(マスターは共有しない)
3. そのスプレッドシートのURL `https://docs.google.com/spreadsheets/d/【ここ】/edit` の【ここ】(ID)をメモ。手順3で `PORTAL_SHEET_ID` に入れる

### 2. Google のログイン用IDを作る(初回だけ)

1. https://console.cloud.google.com/ を開き、新しいプロジェクトを作る(名前は何でも可)
2. 「APIとサービス → OAuth 同意画面」→ ユーザーの種類「外部」→ アプリ名と自分のメールを入れて保存。公開ステータスは「テスト」のままで構いません。「テストユーザー」に**自分のGmailを追加**
3. 「認証情報 → 認証情報を作成 → OAuth クライアント ID」→ 種類「ウェブ アプリケーション」
4. 「承認済みの JavaScript 生成元」に `https://<GitHubのユーザー名>.github.io` を追加して作成
5. できた「クライアント ID」(`〜.apps.googleusercontent.com`)をメモ

### 3. Apps Script を設置する

(Googleスプレッドシートの言語・地域は日本、タイムゾーンは「(GMT+09:00) 東京」にしておいてください。ファイル → 設定。経費データの日付が今日の日付で自動的に入るために使います)


1. 手順1のスプレッドシートで「拡張機能 → Apps Script」
2. 最初から入っているコードを消して、`apps-script/Code.gs` の中身を貼り付けて保存
3. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」に3つ追加
   - `CLIENT_ID` = 手順2でメモしたクライアント ID
   - `ALLOWED_EMAILS` = あなたのGmail(見せたい人が増えたらカンマで区切って追加)
   - `PORTAL_SHEET_ID` = 手順1-2のポータル専用スプレッドシートのID(アプリは、あなたの権限でそちらも読みます。ポータル担当のスタッフにはマスターの中身は見えません)
4. 右上「デプロイ → 新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**(ログインの本人確認はスクリプト側で行い、許可したメール以外には何も返しません)
5. 表示された「ウェブアプリのURL」(`…/exec`)をメモ。初回はGoogleの許可画面が出る(ほかのスプレッドシートを読む許可を含む)ので許可

コードを直したときは「デプロイ → デプロイを管理 → 編集 → 新バージョン」で更新します。

### 4. アプリに設定を書く

`js/config.js` を開いて2つを入れます。

```js
APPS_SCRIPT_URL: 'https://script.google.com/macros/s/……/exec',
GOOGLE_CLIENT_ID: '……apps.googleusercontent.com',
```

この2つは公開されても悪用できない値です(ログインしていないとデータは返りません)。

### 5. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る(Public)。このフォルダの中身を全部アップロード
2. 「Settings → Pages → Branch: main / (root)」で保存
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

### 6. Galaxy(Android)にアプリとして入れる

1. Chrome で上のURLを開き、ログインして表示されることを確認
2. 右上「︙」→「アプリをインストール」または「ホーム画面に追加」
3. ホーム画面のアイコンから、アプリとして起動できます

## アラートの入力のしかた

- アフターメンテ: 顧客の「メンテ1か月」「メンテ5年」「メンテ10年」(AQ・AR・AS列)に、点検した日か記号(○など)を入れる。何か入っていれば消える(予定日は完工日から自動)
- ポータルのキャンセル: 紹介日から6日たっても「結果」が空欄の案件を知らせる(7日を過ぎると課金)。結果に何か入れると消える
- ポータルの見積り: 現調日から7日たっても見積日が空の案件を知らせる。見積日を入れると消える
- 自社の反響は、現調時に見積日を決めるのでアラート対象外
- 日数などは「設定」シートの『値(入力)』で変えられる
- 経費データは、費目の金額を入れると日付(A列)が今日の日付で自動で入る(Code.gs の onEdit)。入金・出金は1つの「入出金」シートに1行ずつ入力し(種別で入金/出金を選ぶ)、金額を入れると日付が同じように自動で入る。月次の入金・現場支払・固定費・広告費は、非表示にしてある年別シート(2024〜2027)に入力する(見るのは「年間収支」シートで、左上の黄色いマスで年を選ぶ)。アプリはこの年別シートを読む
- 自社・訪販は、結果に応じて行の色が自動で変わる(条件付き書式)
- 反響は「自社」「訪販」のタブ(ポータルはポータル担当のスタッフと共有する別ファイル)に、一番下の空いている行へそのまま入力する(行を足す必要なし。日付形式・プルダウンは2000行目まで設定済み)。区分の列は無く、タブ名で決まる
- アプリの「入出金」画面: 総未入金・総未出金、入金日が入っていない案件ごとの残り(案件をタップすると入出金の明細)、入出金の記録(新しい順)。顧客シートにない名前を入力すると画面の上に知らせる
- 入出金の顧客名とインセン調整の顧客名のプルダウンは、スプレッドシートを開き直して上のメニュー「ケイトホーム」→「顧客名のプルダウンを設定」を1回押すと自動で作られる(初回は権限の許可が出るので許可する)
- アプリの「インセン」画面: 着地利益×歩合率(通常20%、ポータル系10%)、クロ40%:アポ60%、入金日の翌月に計上。金額を変えたい案件は、スプレッドシートの「インセン調整」(顧客名/対象(クロ・アポ、空欄なら案件全体)/上書きする金額(円)/理由)に入れると、アプリの計算より優先されPDFに「調整あり」と出る。担当者の選択肢から外したい名前は、設定シートに項目「インセン対象外の担当」(値=名前。複数はカンマ区切り)の行を足す
- IDの入力は不要。反響と顧客は邸名(苗字)と日付でアプリが自動で結びつける。入出金は「顧客名」(苗字+邸。顧客シートで入金日が入っていない案件がプルダウンに出る。地域は顧客の住所から自動。右側に総未入金・総未出金と案件ごとの残が自動で出る)で、インセン調整は顧客シートの名前(プルダウン)で案件を指定する

## 注意

- `tests/real.json` や `.xlsx` など**実データはリポジトリに入れない**でください(`.gitignore` 済み)
- ログインの有効期限は約1時間です。切れたら自動でログイン画面に戻ります
- 完工日が入っていない案件は、利益率の計算に入れません(案件の件数には数えます)。経費が確定していないためです
- 数字の決め方(追加・下請けの扱い、成約率、利益率、契約月ベースなど)は、スプレッドシートの「設定」シートに書いてあるルールと同じです

## 開発者向け

```
node --test tests/engine.test.mjs          # 計算ロジックのテスト
node tests/code_gs_check.mjs               # Code.gs の認証テスト(模擬環境)
KATE_REAL_JSON=/手元/real.json node --test tests/engine.test.mjs   # 実データと既存シートの数字を突き合わせ(手元だけで)
python3 tests/make_sample.py               # 練習用データを作り直す
```

- `js/engine.js` … 計算(画面に依存しない)
- `js/screens/*.js` … 各画面
- `js/ui.js` … 表・グラフ部品(棒グラフは自前のSVG。マウスや指で数字が出ます)
- 今後の画面(着工粗利、施工地図、割合グラフ、口コミ、ランキング)は `js/screens/` に足して `main.js` の `ROUTES` に1行足すだけです
